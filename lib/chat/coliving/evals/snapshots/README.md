# 快照（Conversation Replay 的原料）

`pnpm coliving-snapshot -- --household <id> --as-of <时间> --out <名字>` 存到这里。

一份快照 = 某栋房子在**某个时刻**的完整世界状态：人、成员关系、未结的事、
规则、记忆、历史消息、在等谁回话。场景 JSON 里写 `"snapshot": "<名字>"`
就能把它恢复成一栋全新测试屋，然后只喂最后那条消息——测的是
"新代码对那个历史时刻的处理"，中间轮次不重演、不分叉。

## 提交进 git 之前先看一眼

抓取是只读的，可以对着真实住户的房子跑，所以**快照里是真人说过的话**。
手机号在抓取时已经强制换成槽位号（`+15559000001` 这种，不是真号），
但姓名和消息正文是原文。跟 `scenarios/` 里那份真实厨房事故一样，
提交前自己判断这份内容适不适合进仓库；不适合就留在本地，
`.gitignore` 里没排除这个目录是为了让语料能跟着仓库走。

## 槽位号 ≠ 能用的号

场景里写槽位号（稳定、可提交）；每次恢复会现生成一组当次独有的真实测试号，
因为 `person_contact` 上 `(kind, value)` 是**全局**唯一索引——
同一份快照恢复两次用同样的号会直接撞索引，并发跑批必炸。
